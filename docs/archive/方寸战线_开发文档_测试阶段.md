## 1. 项目与原则

- **方寸战线（旧称钢铁经线）**：类《高级战争》的 3D 战棋，iPhone 实机开发，单文件 HTML / PWA，Three.js，GitHub Pages 托管。
- **视觉原则**
  1. **地形是舞台，单位是主角**：地形低矮、克制，任何时候单位都应是画面里最醒目的东西。
  2. **步兵不必与坦克成比例**：每个兵种独立缩放，以"能站进一格、远看分得清"为准，不追求真实比例。
  3. 兵种靠**轮廓和徽章**区分，不靠体量。
- **已放弃**：平原点缀（灌木、小草、碎石）；前方让位（俯视下不需要）；车轮旋转动画（战棋视距看不见）。

## 2. 坐标与比例约定

| 项 | 约定 |
|---|---|
| 坐标系 | y 向上；模型朝向 +z |
| 格 | 2×2 个单位；格坐标 `(cx, cz)` 的中心在世界 `(2cx, 2cz)` |
| 地面 | 陆地 y = 0；水面 y = -0.3；棋盘底座 y = -1.6 |
| 站位圈 | 半径 0.8，圈内不得有凸起物（树干除外，见 §6） |
| 统一缩放 S | `1.8 / 4.21 = 0.4276`（步兵模型高 4.21 → 世界 1.8） |
| 相机 | 正交；俯角 55° / 62° / 70°；90° 步进旋转；基准方位 `camA = angle + 0.08π` |
| 视距三档 | 5 / 7 / 9 格（正交 span = 10 / 14 / 18）；缩放后自动吸附到最近一档 |

## 5. 测试页 `battle_test`

### 5.1 文件与构建
```
index.html  main.js  world.js  bundle.mjs  loader.mjs  package.json
units/    tank-family.js light-tank-v1_4.js light-track-v1_4.js medium-tank-v2_2.js
          heavy-tank-v1_1.js track-path.js artillery-v2_0.js soldier.js
terrain/  palette.js terrain-batch1.js terrain-nature.js terrain-buildings.js
vendor/   three.module.js
```
- `world.js`：无 DOM，场景、地形、单位、选中移动、让位逻辑都在这里，可在 Node 里跑。
- `main.js`：渲染循环、相机、触屏、界面。
- `node bundle.mjs` → 生成 `battle_test_offline.html`（约 2 MB 单文件，模块以 blob URL 动态加载，**不依赖 importmap、不需要服务器**）。
- **Node 验证方法**：解出 bundle 里的 FILES / ORDER / DEPS，把每个模块改写成 `data:` URL 依次导入，再调用 `buildWorld()`；也可用 `loader.mjs` 把 `three` 映射到 `vendor/three.module.js`。

### 5.2 `buildWorld()` 接口摘要
`{ scene, units, trees, buildings, state, mountain, ground(getter), groundY, apply(camAngle), update(dt, camAngle), cull(camera), animate(t), select/deselect/canMoveTo/moveTo, cellFromRay(ray), reachable(u), cycleOwner(cell), stats(), MOVE, tkey, TREE_LABELS, SIZE_LABELS }`

`state` 关键字段：`treeMode`（0 现状 / 1 挤开 / 2 透视）、`sizeMode`（0 原始 / 1 战棋比例 / 2 步兵小队）、`clsK`（各兵种系数）、`floorTint`、`terrBadges`、`badges`、`annexPush`、`bldFollow`、`sandbox`、`cull`、`idle`、`yieldOn`（默认 false）、`treeK`、`mtnK`、`unitK`、`artK`、`artElev`。

### 5.3 地图（8×10，格坐标 x -4..3，z -5..4）
- 道路网：主路 `cz=0` 自 x -4..3，加南向支路 `(1,1..3)`、`(3,1..2)`、`(-1,-1)`、`(-1,1..2)`，自动出现直 / 弯 / T / 十字 / 终点。
- 林：成片 3×3（x -3..-1，z -4..-2）；孤立林格 `(2,-1) (3,-5) (0,-5) (-1,4)`；两格小丛 `(-4,3) (-4,4)`。
- 山：`(1,-3) (2,-3) (2,-2)` 与单格 `(-4,-3)`。
- 海：东南角 2×2 `(2,3) (3,3) (2,4) (3,4)`。
- 建筑：蓝总部 `(0,3)`、红总部 `(3,-4)`、大城市 `(-3,1)`、小城市 `(0,-2)`、蓝兵工厂 `(-4,1)`。
- 12 个单位：蓝（中坦、重坦、轻坦、火炮、步兵×2）与红（中坦、轻坦、火炮、步兵×3）。

### 5.4 玩法与规则（仅测试用）
- **操作**：点单位选中 → 青色高亮可达格 → 点格移动；点空白取消；点空地上的建筑（无选中时）切换归属：中立 → 蓝 → 红。
- **移动力**：步兵 3、轻坦 6、中坦 5、重坦 4、火炮 4。
- **地形消耗**：平原 / 道路 / 建筑 1；林：步兵 1、其余 2；山：仅步兵，消耗 2；海：不可通过。友军可穿过，敌军挡路；不能停在有人的格子。
- **动画速度**（单位/秒）：步兵 3.0、轻坦 5.0、中坦 4.4、重坦 3.6、火炮 3.8；转向速率 10 rad/s。

### 5.5 界面开关
视距（5/7/9，自动吸附）· 俯角（55/62/70）· 旋转 90° · 树木（现状/挤开/透视）· 尺寸（原始/战棋比例/步兵小队）· 五个兵种缩放滑块 · 地块底色 · 地形角标 · 兵种标识 · 附楼挤开 · 建筑跟随视角 · 沙盘边缘 · 视锥剔除 · 待机动画 · 按需渲染 · 站位圈 · 复位；另有树高 / 山高 / 单位大小 / 火炮大小 / 火炮仰角滑块与"面板"折叠按钮。

### 5.6 渲染
- **按需渲染**：默认只在拖动、缩放、滑块、按钮、移动时画帧；关掉即持续渲染，用来测 fps。
- **视锥剔除**：单位级球体剔除，半径 2.8；可关闭对比。
- **待机动画**：整单位微动（步兵呼吸 / 重心 / 转头、坦克怠速加炮塔缓扫、火炮炮管微摆），30 帧上限，**会失去按需渲染的省电**，默认关。
- 步兵：原 290 个 Mesh 按材质烘焙合并后使用，每队一套材质（迷彩顶点色材质叠队色，**头盔壳也会被染色**）。

## 6. 单位与地形的遮挡方案（已定）

**核心问题**：重坦实际占地 1.66×2.54 比一格还大，压在林格或建筑格上会把地形盖住；而全局缩小又会让步兵太小。

**已定方案**
1. **各兵种独立缩放**（战棋比例）：重坦缩到约 0.8，让它能站进一格；步兵放大 ×1.3。
2. **树木"挤开"**：
   - 只避让**树干**（半径 0.14，加 0.06 余量）；树冠可以盖住单位。
   - 树干落在车身占地内时，被推到车身边缘外；**优先选仍在本格内、位移最小的位置**（实测重坦 0.8 时三种林格均 0 棵出格，最大位移 0.84）。
   - 位置变化带缓动（单帧最大跳变 1.08 → 0.39）。
   - 成片林保持约 5.7 棵/格的抖动网格（间距 0.85）；**孤立林格随机 2–3 棵**。
3. **建筑附楼"挤开"**：单位进驻时，被占位的小楼向侧边滑开（约 0.25 s）；离开后滑回；没位置时退回隐藏。
4. 备选（可对比）：树木透视（树和驻扎中的建筑变半透明，**不推荐**，会发"鬼"）、步兵小队（每步兵单位画 3 个兵，可见三角面约翻倍，**依赖 LOD，暂缓**）。
5. 辅助：地块底色（林格深绿、建筑格浅灰米）、地形角标（林 / 山 / 城）。

## 7. 棋盘边缘"沙盘化"

- 范围：地图四周，一圈带厚度的土层截面（顶面 0 → 底座 -1.6），再加外扩的深色基台。
- 土层（自上而下）：草缘（悬垂、下沿不规则）、土 1、**薄砾石层**、土 2、岩 1、岩 2；**层界随位置噪声起伏**（土 / 砾石 / 岩分界在 ±0.1–0.2 内波动）、层内颜色渐变加三角面随机微扰、壁面有凹凸、嵌入向外微凸的小石块。
- 水截面：海格靠边处用青蓝由浅到深三档不透明渐变（**占位，等 Astra 的 `WATER_PALETTE`**）。
- 当前：边缘共 3,481 三角面（一次性静态几何）；法线均朝外，无 NaN、无退化面。
- **效果是否"像土和岩"未经实机验证**，用户之前认为旧版"太平整"。

## 12. 已知问题 / 风险
- 重坦原始全长 2.54 超过一格，必须缩小才站得下。
- 步兵现在是整体滑行，腿不动（5.2 无分层）。
- 自行火炮车体与轻坦几乎一样大，正面主要靠炮管区分。
- 建筑驻扎 / 空置切换是直接切换，附楼挤开靠滑动缓和，主楼归位有一次"跳变"。
- 附楼挤开只保证不出格，**未检查是否撞到主楼**。
- 树木透视用 `transparent` 材质，存在排序瑕疵。
- 地块底色开关会重建棋盘网格，有极短停顿。
