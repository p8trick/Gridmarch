## 1. 项目与设备
- 回合制战棋（类《高级战争》，旧称钢铁经线），3D（Three.js）、iOS 独立 PWA、GitHub Pages、仓库 `Gridmarch`。
- 设备只有两台：iPhone 17 Pro（横屏 874×402）与 iPad 2025 基础款（横屏 1180×820）。iPhone 竖屏锁定时用虚拟横屏当横屏玩（§5）；iPad 用真横屏。
- 第一阶段目标【已定】：同一台设备上双方轮流操作的"纯战斗"；**11 种陆军**；暂不做 AI、联机、天气、昼夜、迷雾、编辑器。最终要有"选中 → 移动范围 → 走位 → 攻击 → 结束回合"这条线的真实手感。
- 规则基准【已定】：参考 GBA《高级战争2》，部分改成我们自己的想法；血量 10 HP（内部 100 点，显示按格数）；合流溢出血量返现 0.9（`joinRefund`）。
- 玩法要点【已定】：无战争迷雾；**取消指挥官，改为"军队风格"**（均衡型 / 火力型 …，攻防等系数直接给军队，省掉指挥官立绘；先只做均衡型，以后按高战风格增加，还要有"随机"、"自选风格"等更细的选项）；所有单位有燃料和弹药，补给做成配置开关；城市分大小；每方单位上限 40、总 80；沼泽里的地面单位（含步兵）结束回合时掉 1 格血，可致死。

## 2. 已定决策
**技术 / 流程**
- ES 模块 + importmap（不是全局 script）；**不做 Service Worker**（稳定后再议）；**不做离线单文件包**；美术文件不手改（见 ARCHITECTURE）。
- **整个游戏只有一个 html（0.30 起）**【已定】：主页（`#homeView`）和战场（`#battle`，模块 `src/battle/main.js`，点「单人对战」才按需载入）是 `index.html` 里的两个视图，切换只改 `hidden`，不跳转页面——这样 iOS 左右边缘滑动（系统前进 / 后退手势）没有历史可翻，正常游戏里不再触发（你真机确认过；只有跳去开发者测试页才会）。战场用 `mountBattle(host, stage, opts)` / `unmountBattle()` 挂载 / 拆除（停循环、摘监听、释放世界 / 渲染器 / WebGL 上下文）；「换图」原地重建。开发直达：`index.html?go=battle&seed=数字&debug=1`。`battle.html` 已删除。舞台（虚拟横屏）全程只创建一次，主页和战场共用。
- 版本号只在 `index.html` 的 `GM_VERSION`，主页右下角显示，**战场里不显示**。`index.html` 用 `<!--GM-BOOT self="1"-->`（无 entry，只生成 importmap，版本取自自己的 `GM_VERSION`）；测试页 `<head>` 里的 `<!--GM-BOOT entry=… css=…-->` 读取网址 `?v=`，给所有 js 加版本号，绕开 iOS 死缓存；直接打开测试页（无 `?v=`）用时间戳。新增 / 删除 / 重命名 `src/` 下的 js 后运行 `npm run stamp`。
- 测试页放 `tests/`，只调用 `src/` 里的正式文件：`units-terrain.html`（定单位大小）、`orientation.html`（虚拟横屏诊断）、`ui-style.html`（界面风格对比，见下）。**要能单独加到主屏幕的测试页，`<head>` 里必须有 `apple-mobile-web-app-capable=yes` 和 `apple-mobile-web-app-status-bar-style=black-translucent`**（0.31：`units-terrain.html` 缺这两行，单独加到桌面时顶部多出 62px 空白；从主页跳过去没问题，是沿用了主页窗口的样式）。
- 本地存储键统一前缀 `gridmarch.`；素材放文件夹不内嵌代码；引擎代码里不得出现像素尺寸。
- 全屏布局（见 §5）：`html,body` 用 `width:100vw; height:100vh`，不用 dvh，**也不用 `position:fixed; inset:0` / `height:100%` / `innerHeight`**（iPhone 竖屏独立窗口里它们矮 62，见 §5；你的 PWA 全屏指南同理）。

**地形与美术**
- 16 类地块：平原、树林、山地、河流、海洋、海岸线（浅滩 / 断崖）、沙漠、沼泽、总部、大城市、小城市、兵工厂、机场、船坞、公路、桥梁。
- 平原没有模型：棋盘两色交替 `P.grass #8CC63F` / `P.grassAlt #7DB836`。
- 山：A / B 两种风格共 8 个面随机摆放，**没有**相邻自动联结。
- 沙漠：`varied` 变体 ×0.6（每格一座沙丘，高度 / 朝向 / 长度各不同，约 1/3 格有仙人掌，最高约 0.4）。沼泽：每格水洼位置不同，道具按格随机（标准 55% / 芦苇丛 25% / 枯木 20%）。两者整格自带地表，连片格子一次生成。
- 沼泽站位深浅：每格固定 0.02–0.09；`MIRE`（world.js）里 `perTurn=0.03`、封顶 0.14，单位带 `mireTurns` 时每回合多沉。**目前只是接口**，引擎接入后由引擎维护 `mireTurns`（你说想试，测试页有「沼泽停留 N 回合」按钮）。
- 单位按兵种独立缩放（战棋比例，不追求真实比例）：重坦缩到约 0.8，步兵放大约 1.3。**具体系数【待定】**（坦克家族、自行火炮在地图上不好区分，等所有模型到齐在 `tests/units-terrain.html` 的滑条里比较后固定）。
- 遮挡方案：树木只避让树干（半径 0.14 + 0.06 余量），优先本格内位移最小，带缓动；建筑附楼被单位占位时侧滑让位，没位置就隐藏；成片林约 5.7 棵/格，孤立林格 2–3 棵。
- 坐标与比例：y 向上；一格 2×2 世界单位，格 `(cx,cz)` 中心在 `(2cx,0,2cz)`；陆面 y=0，水面 −0.3，棋盘底 −1.6；站位圈半径 0.8；步兵统一缩放 `1.8/4.21`。

**相机（战场页）**
- 正交，固定俯角 55°。视距 5 / 7 / 9 / **11**（0.57 加）档 = **屏幕短边方向的地面格数**（不是屏幕宽度；旧文档按宽度算是错的，已纠正）；双指 / 滚轮自由缩放（3.5–11 格），松手吸附最近一档；缩放时右上旋转按钮临时显示视距数字（§2「战场界面」）；90° 旋转带 0.4 秒动画，旋转中心 = 屏幕正中心对应的地面点；建筑朝向在转过 45° 时切换。

**战场格子光圈（0.36–0.38，`src/battle/cursor.js`）**
- 风格对齐模型：四个转角"厚护角"（浅金色 + 深蓝描边）+ 淡底色，点中时从大一圈落下弹一下再轻微呼吸；点到建筑多一颗自转浮动的菱形水晶。颜色 `COLORS`、粗细 `SIZE`、被挡部分透明度 `GHOST` 都在文件顶部，以后单位选中 / 移动范围沿用。光圈显示时约 30 帧/秒重画，没有光圈时按需渲染。
- 贴地方式：光圈画在真实地面，没被挡住的部分实心，被建筑 / 山体 / 树冠挡住的部分半透明（`GreaterDepth`）。高度取样 `world.surfaceY(cx, cz, x, z)`（桥面 → 桥面高度；山体 → 山脚；沙漠 → 沙丘起伏；河 / 海 → 水面；海岸格 → 锚点高度；沼泽 → 0；其余 → 平地 / 建筑底面）。`groundY` 是"单位站的高度"（山体返回山顶），**画格子光圈别用它**；`baseY` 山体取山脚。四角和底色（8×8 细分）各自取样，所以跟着沙丘 / 桥面起伏。点桥时 `cellFromRay` 会按桥面高度再取一次，选中桥格而不是桥后面的格子。
- 真机前验证：第一关里的平地 / 公路 / 树林 / 山 / 沙漠 / 海 / 桥 / 浅滩 / 断崖 / 沼泽 / 总部 / 大小城市 / 兵工厂都在无头浏览器里点过并看了截图，数值无异常；你真机看过，除机场、船坞外都说可以。

## 5. 虚拟横屏（iPhone 不能锁横屏）
- 现状：iOS Safari / PWA 不支持 `screen.orientation.lock()`，manifest 的 `orientation` 也无效；水平仪误判会翻成竖屏。iPad 用系统旋转锁即可（真横屏）。
- 方案【已定】：`src/battle/stage.js`。系统是横屏就原样；系统是竖屏就把整个舞台转 90°，画面仍是横的；配合控制中心的「竖屏方向锁定」= 系统永不翻转 = 等于锁死横屏，手机横着握。`side` 记住灵动岛在左还是右（存 `gm.stageSide`，主页和战场页共用）；「换边」按钮只在战场页、只在画面被旋转时出现；回到主页 / 页面从缓存恢复时会重新读取选择。
- 你的判断【采纳】：回主页横条在竖屏下落在短边，横握时战棋操作主要在画面中间，比正常横屏时落在长边底部更不容易误触。
- 触摸坐标要换算（`stage.toLogical` / `stage.vec`，纯函数，Node 里验证过往返一致）；DOM 按钮由浏览器处理，不用管；舞台逻辑尺寸用 `stage.w/h` 代替 `innerWidth/innerHeight`；主页 CSS 里用 `var(--sw)` / `var(--sh)`（舞台宽高的 1%）代替 `vw/vh`。
- 真机状态：伪横屏的画面方向、触摸换算没问题；主页在竖屏锁定下可用（你反馈过换边按钮和版本号位置，已改）；`tests/units-terrain.html` 竖屏 0.28 起铺满；**战场页 0.26 起上线，尚无明确反馈**。
- **全屏规则（0.25 在测试页真机验证）**：iPhone 竖屏独立窗口里，`innerHeight`、`height:100%`、`position:fixed; inset:0` 都只有 812（`screen` 874，差 62），页面底部手势区一侧会留白；`width:100vw; height:100vh` 才是整屏。所以：`html,body` 用 100vw×100vh；画布 / 舞台尺寸取 100vw×100vh 探针（`stage.js`；`src/app/main.js` 的 `vp`）；固定在屏幕底部的元素用 `bottom:calc(100% - 100vh)` 补回；舞台内的元素用 `absolute`。去掉 `env(safe-area-*)`、轮换七种测量方式都**不是**原因，别再走这条弯路。
- **安全区**【已定，你 0.30 真机验证后改了结论】：**完全不用 `env(safe-area-*)`**（0.29 给 `units-terrain` 顶部加过 `env(safe-area-inset-top)`，从主页跳转过去没问题，但单独打开该页顶部会多出空白）。竖屏使用的浮层改用**固定顶部距离 52px**（`src/app/ui.css` 的 `--top-safe`；灵动岛下沿至少约 51px，你说想再往上贴一点，现在还有一点点缝）。

## 10. 教训（省额度）
1. iPhone 竖屏独立窗口里 `innerHeight` / `height:100%` / `fixed; inset:0` 矮 62，要用 100vh（§5）。先看你的 PWA 全屏指南，再动代码。
2. 没有证据别改正式页面：先在测试页做对照开关，让你一次试完，再把结论并回。
3. 排查用的开关不要存 `localStorage`；诊断功能（长按「换边」）留着。
4. 凡是"铺到屏幕底"的页面都要检查是否用了 `innerHeight` / `height:100%` / `fixed; inset:0`。
5. 交付一律给两个包：完整包做基准，升级包手机直接传根目录。**发布文件必须调用 `present_files`**，只写到 outputs 目录你点不开（0.30 出过一次）。
6. **打包命令用 `&&` 串联**：测试 / 检查没过就不能出包（0.34 出过一次，修好后重打）。
7. 不用 `env(safe-area-*)`：同一页从主页跳转没问题、单独打开却多出空白（§5）。顶部浮层用固定 52px。
8. 测试页要单独加到主屏幕，必须自带 iOS 全屏 meta（§2）。
9. `groundY`（单位站位高度，山体返回山顶）≠ `baseY`（山脚）≠ `surfaceY`（任意点可见表面）；画贴地的东西用 `surfaceY`（§2 光圈）。
10. 提点子时先查仓库里现有代码再设计（本窗口光圈、界面风格都是先读 `world.js` / `main.js` / `home.css` 再动手，没出返工）。
11. **增量升级包漏传一个，仓库会半新半旧**（0.41 漏传，`data.js` 新、`level1.js` 和测试还旧，CI 红）：拿不准就传完整包。**GitHub 的 `checks` 在你上传 zip 的那次提交上必红**（那时仓库还是旧状态、zip 没解开），真正要看的是 `gridmarch-bot` 提交后的那一条；它红了才点进去展开 `Run npm test` 看最后十几行。（可在 `checks.yml` 加 `paths-ignore: ['*.zip']` 消掉这条误报，你选择先不改，把红灯当提示。）
12. **`npm test` 不跑浏览器，抓不到运行时错误**：0.46 的 `resetView` 定义在 `build()` 里、`close()` 在外面调用，关面板才报错，0.48 才修。改了界面脚本一定要跑 `tools/smoke-arsenal.py`（打开 → 操作 → 关闭 → 重开）。
13. 在容器里读中文文件别用 `cut -c` / `head -c`（按字节切会切断 UTF-8、整条输出作废），用 Python 切片；跑无头浏览器前先重启静态服务（`setsid nohup python3 -m http.server 8099 &`，它会随某些命令结束而退出）；一条命令别连跑太多次完整测试（单条命令超 300 秒会被杀）。
14. DOM 盖在 WebGL 画布上想"透出画布"：窗口的所有祖先都不能画底色（用外扩阴影造边框，见 §2）；DOM 的 z-index 要高于战场按钮，或打开时隐藏它们。
15. 给你演示画面时先看风格、再调参：展台试了纯黑、玩具转盘都被否，最后是"无转盘 + 摄影棚背景 + 软落影"；以后做新界面先给 2–3 个方案让你选，别直接堆一版。
16. **升级包文件名必须以「升级包」开头**：机器人只看文件名，`Gridmarch_v` 开头一律当完整包，会把仓库清成只剩包里的文件（0.50 把补丁命名成 `Gridmarch_v0_51_patch.zip`，你被清空了仓库，靠完整包恢复，当时漏掉的更新记录 / 快照在 0.53 补回）。
17. **管道会吞掉退出码**：`测试 | tail && 打包` 里测试失败也会继续打包（0.58 出过一次）。测试单独跑、看真实退出码，再 `&&` 串联打包。
18. **无头浏览器截动画别靠 `wait_for_timeout` 对时间**（软件渲染下帧很慢，定时器会被拖后）：用 `document.getAnimations()` 暂停并设 `currentTime` 逐帧看；要验证「出现过」就挂 `MutationObserver` 记录，别在固定时刻断言。
19. **动画只动 `transform` / `opacity`**：`left`、`border`、`background-clip:text` + `filter`、同一元素同时斜切 + 动画，都会在 iOS 上闪或跳（0.58 横幅「条纹」的成因）；斜切带本体静止，动画放在外层。
20. **虚拟横屏里原生滚动不可靠**：`touch-action` 按物理屏幕算，旋转舞台里的滚动列表第一下会卡；要自己处理滑动（§2 兵工厂左盒）。
21. 容器里没有的流程别猜：先读 `tools/pack.mjs`、`apply-package.py`、`HANDOFF §0.4`、`CHANGELOG` 的惯例再交付（0.50–0.52 没读就出包，漏了快照和更新记录）。
