## 1. 项目与设备
- 回合制战棋（类《高级战争》，旧称钢铁经线），3D（Three.js）、iOS 独立 PWA、GitHub Pages、仓库 `Gridmarch`。
- 设备只有两台：iPhone 17 Pro（横屏 874×402）与 iPad 2025 基础款（横屏 1180×820）。竖屏不适配。
- 第一阶段目标【已定】：同一台设备上双方轮流操作的"纯战斗"；9 种陆军；暂不做 AI、联机、天气、昼夜、迷雾、编辑器。最终要有"选中 → 移动范围 → 走位 → 攻击 → 结束回合"这条线的真实手感。
- 玩法要点【已定】：无战争迷雾；无主动指挥官技能；所有单位有燃料和弹药，补给做成配置开关；城市分大小（收入与修复不同）；合并溢出血量按金钱返还（`joinRefund` 默认 0.9）；每方单位上限 40、总 80；沼泽里的地面单位（含步兵）结束回合时掉 1 HP，可致死。

## 2. 已定决策
**技术 / 流程**
- ES 模块 + importmap（不是全局 script）；**不做 Service Worker**（稳定后再议）；**不做离线单文件包**；美术文件不手改（见 ARCHITECTURE）。
- 版本号只在 `index.html` 的 `GM_VERSION`，主页右下角显示，**战场里不显示**。各页面 `<head>` 里的 `<!--GM-BOOT …-->` 启动脚本读取网址 `?v=`，给所有 js 加版本号，绕开 iOS 死缓存；直接打开页面（无 `?v=`）用时间戳。新增 / 删除 / 重命名 `src/` 下的 js 后运行 `npm run stamp`。
- 测试页放 `tests/`，只调用 `src/` 里的正式文件。test1、test2 作废；`tests/units-terrain.html`（原 test3）保留，用来定单位大小。
- 本地存储键统一前缀 `gridmarch.`；素材放文件夹不内嵌代码；引擎代码里不得出现像素尺寸。
- 全屏布局用 `position: fixed; inset: 0`，不用 dvh（见 `docs/` 外的 PWA 全屏指南 / `HOME.md` 避坑）。

**地形与美术**
- 16 类地块：平原、树林、山地、河流、海洋、海岸线（浅滩 / 断崖）、沙漠、沼泽、总部、大城市、小城市、兵工厂、机场、船坞、公路、桥梁。
- 平原没有模型：棋盘两色交替 `P.grass #8CC63F` / `P.grassAlt #7DB836`。
- 山：A / B 两种风格共 8 个面随机摆放，**没有**相邻自动联结。
- 沙漠：`varied` 变体 ×0.6（每格一座沙丘，高度 / 朝向 / 长度各不同，约 1/3 格有仙人掌，最高约 0.4）。沼泽：每格水洼位置不同，道具按格随机（标准 55% / 芦苇丛 25% / 枯木 20%）。两者整格自带地表，连片格子一次生成。
- 沼泽站位深浅：每格固定 0.02–0.09；`MIRE`（world.js）里 `perTurn=0.03`、封顶 0.14，单位带 `mireTurns` 时每回合多沉。**目前只是接口**，引擎接入后由引擎维护 `mireTurns`（你说想试，测试页有「沼泽停留 N 回合」按钮）。
- 单位按兵种独立缩放（战棋比例，不追求真实比例）：重坦缩到约 0.8，步兵放大约 1.3。**具体系数【待定】**（坦克家族、自行火炮在地图上不好区分，等所有模型到齐在 `tests/units-terrain.html` 的滑条里比较后固定）。
- 遮挡方案：树木只避让树干（半径 0.14 + 0.06 余量），优先本格内位移最小，带缓动；建筑附楼被单位占位时侧滑让位，没位置就隐藏；成片林约 5.7 棵/格，孤立林格 2–3 棵。
- 坐标与比例：y 向上；一格 2×2 世界单位，格 `(cx,cz)` 中心在 `(2cx,0,2cz)`；陆面 y=0，水面 −0.3，棋盘底 −1.6；站位圈半径 0.8；步兵统一缩放 `1.8/4.21`。

**相机（战场页）**
- 正交，固定俯角 55°。视距 5 / 7 / 9 档 = **屏幕短边方向的地面格数**（不是屏幕宽度；旧文档按宽度算是错的，已纠正）；双指 / 滚轮自由缩放（3.5–11 格），松手吸附最近一档；90° 旋转带 0.4 秒动画，旋转中心 = 屏幕正中心对应的地面点；建筑朝向在转过 45° 时切换。

**第一关（`src/game/levels/level1.js`）**
- 20×12，红蓝左右镜像（x → −1−x），蓝方在西。随机只在蓝方半边生成再镜像，所以双方地形完全对称。
- 一切由种子决定：水域（居中矩形湖 / 不规则湖 / 左右各一池 / 没有湖）、河流（约一半的图有，竖向小河 + 一座公路桥，镜像到红方）、湖上跨海桥（仅矩形湖、桥头落在直岸时，约 1/4 的图）、基地行号、城市位置、公路走向、山、沙漠、沼泽、树林。
- 固定内容：红蓝总部各配 2 座兵工厂，中立 2 座大城市 + 6 座小城市（蓝半边 1 大 + 3 小，镜像）。
- 每次打开不带参数就是新随机种子（左下角显示，`?seed=数字` 固定复现）。生成器带自动重试；300 个种子全部合格；`npm test` 检查种子 1。
- 开局没有单位（单位 / 生产由规则引擎负责）。

## 5. 虚拟横屏（iPhone 不能锁横屏）
- 现状：iOS Safari / PWA 不支持 `screen.orientation.lock()`，manifest 的 `orientation` 也无效；水平仪误判会翻成竖屏。iPad 用系统旋转锁即可。
- 方案【已定】：`src/battle/stage.js`。系统是横屏就原样；系统是竖屏就把整个舞台转 90°，画面仍是横的；配合控制中心的「竖屏方向锁定」= 系统永不翻转 = 等于锁死横屏，手机横着握。`side` 记住灵动岛在左还是右（按钮「换边」）。
- 你的判断【采纳】：回主页横条在竖屏下边缘，横握时落在短边，战棋操作主要在画面中间，比正常横屏时落在长边底部更不容易误触；不为该侧留安全区边距（见下）。
- 触摸坐标要换算（`stage.toLogical` / `stage.vec`，纯函数，Node 里验证过往返一致）；DOM 按钮由浏览器处理，不用管；舞台逻辑尺寸用 `stage.w/h` 代替 `innerWidth/innerHeight`。**不处理安全区**（灵动岛 / 手势区）：画面铺满，控件只留固定小边距，不加空白或白边（战棋基本不点屏幕边缘，先拖动地图再点边缘单位）。
- **【已通过真机测试】**（0.20）：伪横屏效果不错，可接受；iPhone 以后就用这套，配合「竖屏方向锁定」基本都是锁住的（没锁时晃动会让画面跳变，但内容一样）。iPad 用真横屏（系统旋转锁），系统横屏时 `Stage` 不旋转。**0.21 已并入 `battle.html`**：`#stage` 包住整个战场页，指针坐标走 `stage.toLogical`，相机宽高比和画布尺寸取 `stage.w/h`，竖屏提示 `#land` 已删；系统竖屏时左上多一个「换边」按钮（画面上下颠倒就点一下，选择会记住，和横屏测试页共用）。测试页 `tests/orientation.html` 保留。
- **0.22 真机反馈**：系统竖屏下的伪横屏，短边（回主页横条那一边）出现黑色空白；系统横屏时是真全屏。原因判断：iOS 独立窗口竖屏时 `innerHeight` 比真实屏幕矮一截。**0.23**：`Stage` 改取 `100vw×100vh` 探针量尺寸（不再用 `innerWidth/Height`）；主页也并入舞台（去掉“请横屏”提示层，`vw/vh` 改 `--sw/--sh`，新增「换边」按钮，主页也不再处理安全区）。**待真机确认**；若还有黑条，打开 `tests/orientation.html` 截图，第一行有 100vh / inner / screen / client 数字。
- **0.23 真机反馈**：改成 100vh 探针后，竖屏下主页和战场页仍有黑边，真横屏是真全屏。代码里已没有任何 `env(safe-area-*)`，所有页面都带 `viewport-fit=cover`。**0.24 加现场诊断，不再猜**：长按「换边」按钮 0.8 秒（主页 / 战场页；`tests/orientation.html` 打开就带）→ 屏幕上画出各单位（fixed / 100vh / lvh / svh / dvh / inner）量到的右边和下边，面板显示数字，并能点按钮现场切换舞台的测量方式（`gm.measure`：vh / lvh / svh / dvh / inner / screen / fixed）；哪种切过去黑边消失，就把它改成默认。

## 6. 架构要点（详见 ARCHITECTURE.md）
- 分层：`art/`（不依赖 game/app）→ `game/`（把美术接成世界）→ `battle/` 与 `app/`（页面层）。
- **规则引擎还没有**，这是下一个大块，目标结构【建议】：`src/engine/`（不碰 DOM、不碰 three，状态是纯 JSON）+ `src/data/`（单位、地形、数值、开关）。所有操作都是"动作"（移动、攻击、合并、生产、结束回合），`engine.apply(action)` 返回"事件列表"，渲染层只消费事件做动画；这样撤销、回放、存档、AI、联机都能复用。引擎只认单位 id，不知道模型存在；`modelKey` 在渲染层注册表里查。
- 地图数据：`width / height / terrain[] / owner[] / units[]` + 元信息；地图、存档、编辑器共用一套 JSON。
- 当前 `world.js` 是"测试页世界"，渲染与玩法混在一起（通行代价 `costOf`、站位、开火都在里面，数值是测试用的暂定表）；引擎建好后这些要抽出来。
