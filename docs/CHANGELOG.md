# 更新日志（0.91 起）

> 0.90 及以前的日志在 `docs/archive/CHANGELOG_至0.90.md`（不用读）。每个新版本在下面最上方插一条，5–8 行：做了什么 / 为什么 / 改了哪些文件。

## 0.95 · 音效分两套：菜单 / 游戏本身
- `sfx.js` 拆成两个声音库（`play(名字, 库)`）：**ui = 菜单**（主页、设置、暂停菜单、结算面板、右上角「菜单」键）——保持原来圆润的「啵」玩具盒质感；**game = 真正的游戏内操作**——军事机械味：开关「咔嗒」、电台「哔哔」、冲压「盖章」、棘轮「上膛」。库里名字一一对应，规则仍集中在 `kindOf`（`MENU` 选择器决定哪些算菜单，其余战场内的都算游戏）。
- game 库：`tap` 开关咔嗒（右上角找单位 / 旋转、结束回合状态条、详细面板条目、兵工厂卡片…）· `select` 电台哔哔（选中自己的单位）· `cell` 小「嗒」（点空格 / 地形）· `go` 发动机一轰 + 「收到」（下达移动命令）· `ok` 盖章（占领 / 合流 / 生产 / 开火 / 确认结束回合）· `wait` 轻盖章（待命）· `arm` 棘轮上膛（进入选目标）· `back` 取消（取消选中 / 撤销移动 / 退出选目标 / 点面板外）· `open` 电台静电 + 「滴」（长按详细面板 / 战场情报 / 打开兵工厂）· `deny` 低沉嗡（单位上限、灰的「生产」）。
- **棋盘点按现在也有声音了**（main.js `handleTap` 里直接 `sfx.play(名字, 'game')`）：选单位、点空格、取消选中、走、撤销、打。
- 测试：`smoke-sfx` 新增库归属断言（主页 / 暂停菜单 / 菜单键 = ui，找单位键 / 点单位 = game/select / 点别处 = game）。规则测试不变（36 项）。
- 改动文件：`src/battle/{sfx.js,main.js}` `tools/smoke-sfx.py` `index.html`（版本号）`docs/CHANGELOG.md`。

## 0.94 · 界面音效 + 主页左移 80px
- 新增 `src/battle/sfx.js`：**界面音效，全部用 WebAudio 现场合成（没有音频文件）**。在 `document` 上挂一个捕获阶段的 click 监听（`home.js` 启动时 `sfx.install()`，只挂一次），主页菜单 + 战场所有按钮 / 菜单自动出声，不用逐个按钮接线：
  - `tap` 普通点按（软「啵」，每次音高有 ±3% 微抖）· `ok` 确认 / 开始 / 占领 / 合流 / 再来一局 / 单人对战（两个上行音）· `back` 关闭 / 返回 / 继续 / 看战场 / 点面板外暗处（下行音）· `open` 长按打开详细面板 / 战场情报 · `deny` 点了灰的「生产」（低沉嗡）。
  - 点棋盘（canvas）不出声；灰着的按钮（`aria-disabled` / `.off`）不出声；两声之间至少隔 35ms。
  - iOS 要用户手势才能发声：首次 `pointerdown` 时建立并唤醒 AudioContext。注意：iOS 的 WebAudio 受**静音键**控制（响铃 / 静音拨片拨到静音就没声音）。
- 开关：存本机 `gridmarch.sfx`（`'0'` = 关）。主页设置里原来「音量 · 即将开放」改成「音效 开 / 关」（中英文）；战场暂停菜单第一页新增「界面音效 开 / 关」（同一个键）。
- 主页标题 + 左侧菜单整体右移到离左边 **80px**（`home.css` 新变量 `--pad-home: max(5sw, 80px)`；中英文标题都跟着，因为它们和菜单共用同一个内容区的左内边距）。战场各面板仍用 `--pad-l`（56px），边距问题其余部分继续暂缓。
- 测试：新增 `smoke-sfx`（给 `createOscillator` 打计数补丁：点主页菜单 / 战场按钮出声，点棋盘不出声，设置里关了不再出声并存 0，暂停菜单开关同一个键，主页标题 / 菜单离左边 80px）。规则测试不变（36 项）。
- 改动文件：新增 `src/battle/sfx.js` `tools/smoke-sfx.py`；修改 `home.js` `home.css` `index.html` `src/battle/main.js` `docs/CHANGELOG.md`。

## 0.93 · 战场情报
- 新增 `src/battle/intel.js`：**长按右上角「找未行动单位」键约 0.45 秒**打开战场情报（按住时按钮外圈金环慢慢扩开；短按仍是原来的找单位；长按触发后抬手那一下不算点按）。
- 单个大玩具盒（样式复用结算面板的 `.res-*`，外壳 `.res.int`）：蓝红对照 6 行——现存单位 / 已生产 / 损失 / 据点（带各类据点数：总部、大城、小城、兵工厂…）/ 每回合收入 / 军费（现有资金）；当前行动方标「行动中」；底部一条「中立据点」（总数 + 各类）。条形比数量，占优一方数字放大（损失越少越占优）。点盒子外面的暗处关闭。
- 数据来自引擎 `summaryOf` + `incomeOf`；打开时取快照。情报打开时右上角按钮藏起来，结束回合 / 找单位 / 点格等操作都不响应（和详细面板、兵工厂一致）。
- 边距问题（iOS 27 毛玻璃，实测 80px 才基本不影响）暂缓，保持 56px；本面板同详细面板，不吃这个问题。
- 测试：新增 `smoke-intel`（短按 / 长按 / 数字与引擎一致 / 点里面不关 / 点暗处关 / 关后短按仍找单位）；规则测试不变（36 项）。
- 改动文件：新增 `src/battle/intel.js` `tools/smoke-intel.py`；修改 `src/battle/{main.js,battle.css}` `index.html`（版本号）`docs/CHANGELOG.md`。

## 0.92 · 结算镜头对准 + 边距测试页
- 胜负分出后的镜头中心：**占领总部 = 被占的总部格**；**歼灭 = 打出最后一击的我方单位**（反击把攻方打光则是守方）；沼泽拖垮没有「最后一击」，退而求其次用任一胜方单位。引擎新增：歼灭时 `g.winCell` = 那个单位所在格。
- `tests/orientation.html` 新增「边距」测试（iOS 27 顶部毛玻璃避让）：灵动岛一侧画红色避让带 + 黄线（边距，= 游戏里 `--pad-l`，现为 56px）+ 青色虚线（按钮倾斜后的最近角，= 边距 − 4，现为 52px）+ 三排 0~120px 直尺 + 游戏样式的示意按钮；`−5 −1 +1 +5` 微调、直接在屏幕上拖是粗调、「回到 56」复位；数字存本机。打开时自动关掉现场诊断面板（它盖在中央、还带彩色边线）。系统横屏时不知道岛在哪边，两侧都画。**测出合适数字后，`home.css` / `battle.css` 的 `--pad-l` 的 56px 再按它改。**
- 测试：规则 36 项（+1）、新增 `smoke-wipe`；`smoke-result` 不变。
- 改动文件：`src/rules/engine.js` `src/battle/{main.js,orientation-test.js}` `tests/orientation.html` `tools/{check-rules.mjs,smoke-wipe.py}` `index.html`（版本号）。

## 0.91 · 胜利结算面板 + 统计表
- 规则引擎新增**统计表** `g.stats[玩家]`：`built` 生产数 · `lost` 损失数（含沼泽致死）· `killed` 击毁数（含反击击毁）· `captured` 占领数 · `income` 累计收入 · `spent` 累计军费（造兵 + 修理）；另有 `g.winReason`（`hq` / `wipe` / `draw`）、`g.winCell`（占领的总部格）。`forecast` 复制统计表，预估不污染真数据。
- 新增 `summaryOf(g)`：每方 + 现存单位 / 据点数 / 各类据点数，中立据点数及分类——胜利面板和下一步的战场情报共用。
- 新增 `src/battle/result.js`：**胜利结算面板（方案 A 双盒战报）**。左盒 = 胜利牌（盖章「胜利」+ 队伍 + 第 N 天 + 怎么赢的 + 再来一局 / 回主页 / 看战场）；右盒 = 蓝红对照表（已生产 / 损失 / 击毁 / 据点 / 累计收入 / 累计军费，条形比数量，占优一方数字放大）。
- 加了方案 C 的表现：胜负分出时**败方全部压灰**、镜头平移到被占的总部并**缓慢绕场**（碰一下战场或点旋转就停）；「看战场」把面板收成底部细横幅（胜方 · 第 N 天 · 击毁 / 损失 / 据点），点横幅再展开。「再来一局」= 同一张图重开。胜负已分后点左上状态条不再弹结束回合确认。
- 改动文件：`src/rules/engine.js` `src/battle/{result.js,main.js,battle.css}` `tools/{check-rules.mjs,smoke-result.py}` `index.html`（版本号）。测试：规则 35 项（+2）、新增 `smoke-result`。
